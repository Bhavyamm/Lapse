# Review, Trial reminder screen (commit 1646187), 2026-10-17

**Reviewed by**: Sonnet 5.5 (author model: Opus 5.5)
**Scope**: 15 files, `git show HEAD` (Trial screen, `reminders/when.ts`, `remind`/`lead` fields, trial-aware `cancelGuide`, `openSubscription(id, trialRunning)`, Home/All/Calendar rows opening it)
**Verdict**: Changes requested

## Summary
The screen matches the intent and the pieces are well shaped: `when.ts` is pure and works on local dates (`addDays` goes through `setDate`, so DST does not shift the day, and `setHours(9)` is applied after), money stays in integer cents, `update` merges so `lead` and `remind` survive an edit (`toNewSubscription` never carries them), the missing and ended cases redirect instead of crashing, and chips and facts use `role`/`aria-*`. `tsc`, lint and the 15 tests in `trial.test.tsx` and `reminders/` pass. The real problems are: marking a trial as cancelled from the Cancel button lands on a "Not tracked any more" screen, the Cancel button reads "Cancel before on Sat, Oct 25" for trials a week or more out, and a reminder earlier today at 9:00 is shown as still upcoming. I read the code and ran the test suite; I did not run it on a device.

## Critical
None.

## Major
### 🟠 Cancelling from the Trial flow ends on "Not tracked any more", `src/app/trial/[id].tsx:27-32`, `:144`
**Problem**: "Cancel before..." does `router.push` to the detail screen, so the stack is Tabs, Trial, Detail. On "I already cancelled" the detail calls `leave()` (`router.back()`) and then `cancel(id)`. That reveals the Trial screen underneath, whose `sub` is now gone, so it renders `<Redirect>` to `/subscription/[id]`, which shows `<Missing />`. The person finishes the app's main success action and is left on an error-looking page with a back button, one more tap from Home. The same stale screen bites on edit: in Detail, switch the trial off (or move its end date past) and go back, and the Trial screen redirects to a second copy of the detail instead of returning to the list. Neither path is tested (the test only asserts `push` was called).
**Why it matters**: Every trial that is cancelled through the new, primary route goes through this.
**Suggested fix**: Have the Trial screen not depend on a subscription that is gone: when `sub` is missing, `leave()` / `router.dismissTo('/')` instead of redirecting to the detail screen (only redirect when the subscription exists but its trial is over). Better, make "Cancel before" `router.replace` to the detail so the modal is not left underneath. Add a test that renders the screen, removes the subscription from the store and expects no redirect to the detail, and one for `openDetail`.

### 🟠 "Cancel before on Sat, Oct 25" when the trial is a week or more away, `src/app/trial/[id].tsx:39-45`, `:64`
**Problem**: `endsWord` returns `on Sat, Oct 25` for 7 days or more (it is built for the sentence "trial ends on ..."), and `cancelBy` reuses it as `Cancel before ${ends}`. A 7-day trial, the most common length, shows the button "Cancel before on Fri, Oct 23" (and the 14 and 30 day ones too). The tests only cover the 2-day case ("Cancel before Sunday"), so the word-form branch is untested.
**Why it matters**: A wrong, ungrammatical label on the main action, on the most common trial lengths.
**Suggested fix**: Have `endsWord` return the bare word ("Sunday", "Sat, Oct 25") and put the "on" in the lede only for the date form, or build the button label from `formatShortDate`/weekday separately. Add tests at 3, 7 and 14 days for both the lede and the button.

## Minor
### 🟡 The reminder time shows as upcoming after it has passed today, `src/app/trial/[id].tsx:61`
**Problem**: The check is `reminderDay(...) < today`, which compares days only. With a 1-day lead for a charge tomorrow (or "Morning of" on the charge day), the reminder day equals today, so at 2:00 PM the card says "Fri, 9:00 AM" as if it were still coming, while `reminderAt` is already in the past. The test pins the clock to 8:00, so it never sees this.
**Why it matters**: The person is told a reminder is on the way when none will fire, on a screen about not getting charged.
**Suggested fix**: Compare instants: `at.getTime() <= Date.now()` (use a `now` from `useToday`'s tick or `new Date()`), and add a test with the fake clock at 14:00.

### 🟡 Timing chips stay editable when reminders can't fire, with no way to fix it, `src/app/trial/[id].tsx:52-62`, `:123-134`
**Problem**: When `remindersEnabled` is false (the default until onboarding turns it on) or `sub.remind === false`, the card says "Reminders are off" / "Off for this trial" but the chips still change `lead` and the text does not respond. There is no switch here to turn this trial's reminder back on (only the detail screen's "Renewal alert" tile has it), so "Off for this trial" is a dead end on the screen that is about the reminder. The `Off for this trial` branch has no test.
**Why it matters**: Controls that do nothing visible, in an off state the person cannot leave from here.
**Suggested fix**: Disable (and dim) the chips while reminders are off, and add a small "Turn on" action for `remind === false` that calls `update(sub.id, { remind: true })`; test both texts.

### 🟡 Chips are 34 pt tall with no hit slop, `src/components/chip.tsx:28`, `src/app/trial/[id].tsx:123-134`
**Problem**: The three timing chips are the only way to set the reminder, and each is `height: 34` with no `hitSlop`, under the 44 pt minimum used elsewhere (the Close button is 44, "I'll keep it" is 56).
**Why it matters**: Easy to mis-tap on small phones, and the other screens hold the 44 pt line.
**Suggested fix**: Add `hitSlop={{ top: 5, bottom: 5 }}` to `Chip` or raise its height to 44 when `onWhite`.

### 🟡 Routing and copy paths added by this commit have no test, `src/features/subscriptions/open.ts:3-11`, `src/__tests__/trial.test.tsx`
**Problem**: Nothing asserts that `openSubscription(id, true)` pushes `/trial/[id]` while `false` pushes the detail, that Home/All/Calendar rows pass the right flag (Calendar passes `c.trialEnding`, so a later trial month works, but a stale one doesn't), or that a missing subscription redirects (the mock `Redirect` is only exercised for an ended trial). The `remind`/`lead` fields have no store test that `update({ lead })` keeps the other fields.
**Why it matters**: The Major findings above were findable by a test that goes through the whole flow.
**Suggested fix**: A small `open.test.ts`, a missing-subscription test, and one flow test: Trial, "Cancel before", confirm, expect no redirect to a missing detail.

## Nits
- `src/app/trial/[id].tsx:93-101`: `role="heading"` on a View with `aria-label` and a child `AppText` heading in the `Today` case: the two branches expose different structures; label both the same way.
- `src/app/trial/[id].tsx:36`: `leave` runs `router.back()`; on a modal opened from a deep link `router.dismissTo('/')` is safer (same note as the detail screen).
- `src/app/trial/[id].tsx:111`: `PER_YEAR`/`CYCLE_WORD` are copied from `subscription/[id].tsx`; move them to `billing.ts`.
- `src/app/trial/[id].tsx:148-153`: the "I'll keep it" button has no `aria-label`; fine because the text child supplies it, but it reads as the same visual weight as the primary action.
- `src/features/reminders/when.ts:24-27`: `formatReminder` says "Fri" for a reminder 3 days out but gives no date; for a 14-day trial with a 3-day lead the weekday alone is ambiguous.

## Resolution

Fixed:
- Major, cancelling from the Trial flow: "Cancel before" now replaces the Trial screen with the detail, so going back after cancelling or editing lands on the screen the trial was opened from, never on a stale trial.
- Major, "Cancel before on Sat, Oct 25": trials a week or more out read "Cancel before Sun, Oct 25".
- Today's reminder compares the full time (read when the screen opens), so at 2 PM a 9 AM reminder reads "That time has passed".
- The timing chips are hidden while reminders are off. With the reminder off for one trial, picking a time turns it back on, and the card says so.
- Chips get 5pt of vertical hit slop (44pt targets).
- Tests: openSubscription routing, a missing subscription redirecting, the store `update` merge keeping `lead` and `remind`, the replace-on-cancel flow, the 7+ day label, the same-day passed reminder, re-enabling a trial's reminder and hidden chips. 177 passing.

Deferred:
