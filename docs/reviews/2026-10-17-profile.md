# Review, Profile screen (commit b875e59), 2026-10-17

**Reviewed by**: Sonnet 5.5 (author model: Opus 5.5)
**Scope**: 23 files, `git show HEAD` (profile screen, app lock, reminder sheet, settings row, toggle, savings/csv/export, settings and subscriptions stores, app.json plugin)
**Verdict**: Changes requested

## Summary
The commit delivers what the intent describes, and the core logic is sound: the Face ID prompt does not loop (the `wasBackground` guard means the inactive/active pair iOS fires during the prompt is ignored), old saves load fine (zustand's default shallow merge fills `cancelled: []` and `appLock: false`, so no `migrate` is needed), the trial-caught rule matches `overview`/`csv`, the CSV quotes correctly and neutralizes formula prefixes, and the `File`/`Paths` calls match the SDK 57 types. `tsc`, lint and all 139 tests pass. The real problems are around the lock being weaker than it looks: the app switcher still shows the content, a user with no passcode can be locked out for good, and the reminder sheet sits above the lock. Separately, `Alert.alert` does nothing on web, so three user-visible messages never appear there. I read the code and did not run it on a device; the iOS items are from platform behavior and should be confirmed in Expo Go.

## Critical
None.

## Major
### 🟠 The app switcher snapshot shows the content, `src/components/app-lock.tsx:35-39`
**Problem**: The cover is raised only on `AppState === 'background'`. On iOS the system takes the app-switcher snapshot as the app resigns active (`inactive`) and finishes it right after `background` is delivered; the React state update from the `background` handler renders on a later pass, so the snapshot usually contains the real screen (subscription names and amounts). On Android the Recents thumbnail is taken from the window with nothing marking it secure, so the same happens there. The lock does its job on return, but the privacy promise on the lock screen ("Your subscriptions stay private") is not kept in the one place people look when they switch apps.
**Why it matters**: The feature exists to keep the list private from someone who picks up the phone; the switcher is the first thing they see.
**Suggested fix**: Keep two things apart: `covered` (privacy cover, shown on `inactive` and `background`) and `locked` (needs auth, set on `background`). Render the same lock view (no prompt) while `covered`. To stop the Face ID prompt and the notification permission dialog from flashing the cover, set a ref `authenticating` around `unlock()` and ignore `inactive` while it is true. Only apply the cover when `appLock` is on. For Android add `expo-screen-capture` `preventScreenCaptureAsync()` while the lock setting is on (it uses FLAG_SECURE and blanks Recents), installed with `npx expo install` and checked in Expo Go. Verify on a device by opening the switcher.

### 🟠 A phone with no passcode or biometrics locks the person out permanently, `src/features/lock/biometrics.ts:31-38`, `src/components/app-lock.tsx:56-67`
**Problem**: `unlock` collapses every failure into `false`. If the lock is on and the person later removes their passcode (iOS `passcode_not_set`, Android `not_enrolled`/`not_available`), `authenticateAsync` can never succeed, the lock screen stays up, and the only way out is deleting the app, which deletes the data. `getBiometrics()` already knows when the device cannot authenticate but `AppLock` ignores `ready`.
**Why it matters**: A privacy setting that can destroy access to the person's own data with no recovery. It also applies to `lockout` (too many failed attempts) where there is no message at all.
**Suggested fix**: Return the error from `unlock` (`{ ok, error }`). When the error is `not_enrolled`, `passcode_not_set` or `not_available`, set `appLock` to false and open the app (the lock cannot protect anything now), and show a line on the profile row. For `lockout` show "Too many tries, try again in a moment" on the lock screen. Test with a mocked `authenticateAsync` that returns each error.

### 🟠 `Alert.alert` is a no-op on web, so Pro, "can't share" and "export failed" show nothing, `src/app/(tabs)/profile.tsx:68`, `:187`, `:189`
**Problem**: react-native-web's `Alert.alert` is an empty function. The "Unlock Pro" button and "Import a statement" row (whose whole purpose is to say Pro is coming) do nothing on web, and a failed export on web fails silently. The intent calls out web explicitly (download path), and this is the first use of `Alert` in the codebase (the only hits are in this file), so there is no pattern to lean on.
**Why it matters**: Two of the screen's main buttons look broken on web.
**Suggested fix**: Replace `Alert` with an in-app notice used on every platform: a small `Notice`/toast component or an inline message under the button (`role="alert"`), as `ReminderSheet` already does for "blocked". If native `Alert` is kept, branch on `Platform.OS === 'web'` and use `window.alert`, and add a test that covers both.

### 🟠 The reminder sheet is a native Modal above the lock, `src/components/reminder-sheet.tsx:17`, `src/app/_layout.tsx:67-73`
**Problem**: `Modal` renders in its own window above the whole root view, including the lock overlay. If the sheet is open when the app is backgrounded and returns, the sheet shows over the lock screen and can be used (toggle reminders, change lead time) without authenticating; closing it reveals the lock. The same applies to any Alert and to the add sheet (`subscription-editor`, also a Modal) if it is open: its fields, including a subscription name just typed, show through the lock.
**Why it matters**: A lock bypass for settings and for the editor's contents, and it will bite more as Modals are added (the Subscription detail screen).
**Suggested fix**: Close modals when the app locks (a `locked` flag from a small store or context that the sheets read: `visible && !locked`), or render the lock inside its own `Modal` so it stacks above the others (then `onRequestClose` must be a no-op on Android). Add a test: sheet open, background, return, sheet is gone.

## Minor
### 🟡 Clamped month-end anchors drift after a subscription is cancelled, `src/features/subscriptions/savings.ts:19-21`
**Problem**: `toCancelled` replaces `chargeOn` with the next charge date. For a monthly plan anchored on Jan 31 and cancelled in February, that is Feb 28, and every later charge is counted from the 28th (Mar 28, Apr 28) instead of the 31st/30th. A yearly plan anchored on Feb 29 becomes Feb 28 forever. The count is usually the same, but the number of charges up to `today` is off by one in the days after month end, and `calendar.ts` explicitly avoids this drift ("Count cycles from the anchor").
**Why it matters**: The saved total can be one charge short or over for a few days a month.
**Suggested fix**: Keep the original `chargeOn` in the record and add `from: next`; have `summarizeSavings` call `chargesBetween` with `from` set to each record's `from` (or filter charges with `on >= c.from`). Add a test with a Jan 31 anchor cancelled in February.

### 🟡 Day-of cancellations count the charge as saved immediately, `src/features/subscriptions/savings.ts:27-31`
**Problem**: `nextChargeDate` returns today when the charge is today, and `summarizeSavings` includes `today` in its range, so cancelling on the renewal day counts that charge as saved at once, though the bank may already have taken it. For a trial ending today the person is shown "Trial caught" and the first price added.
**Why it matters**: The headline number can overstate by a full price, and the very first cancellation (the demo moment) hits this when someone cancels the sub due today.
**Suggested fix**: Decide and document: count from the day after cancelling (`next > today`), or leave as is and say "charges due since you cancelled". Cover with a test.

### 🟡 `summarizeSavings` walks every cycle from the anchor on each render, `src/features/subscriptions/savings.ts:27-31`
**Problem**: `chargesBetween(..., '0000-01-01', today)` iterates from each record's anchor to today and allocates a `Date` per step. It is memoized on `[cancelled, today]`, and cancelled weekly plans accumulate forever, so cost grows with the number of records and years.
**Why it matters**: Not a bug now; it is a slow, unbounded cost on the first tab people open to see their savings.
**Suggested fix**: Count with arithmetic (cycle counts from the anchor to `today`), or use the `from` field above and iterate only forward. The `'0000-01-01'` sentinel is also a magic string; use `c.chargeOn`.

### 🟡 Lock relocks on every short trip out of the app, including the share sheet, `src/components/app-lock.tsx:36-43`
**Problem**: Any `background` locks immediately, with no grace period. Exporting a CSV into Mail or Files, or copying a code from another app, returns to a Face ID prompt each time. The share sheet is the one flow the app causes itself.
**Why it matters**: People turn off a lock that nags.
**Suggested fix**: Add a short grace window (for example 30 seconds, measured from `background` using `Date.now()`) and skip the lock when the app returns inside it, except always lock on a cold start. Make the window a named constant.

### 🟡 Lock fails open if saved settings cannot be read, and is read once, `src/components/app-lock.tsx:25-26`
**Problem**: `useSettings.getState().appLock` is read when `AppLock` mounts. If AsyncStorage throws, `hydrated` becomes true with defaults (`appLock: false`) and the app opens unlocked. The comment says the layout mounts it after settings loaded, which is true, but a failed load is also "loaded".
**Why it matters**: A storage error is indistinguishable from "lock off". Rare, and the subscriptions store would have failed to load too, so the exposure is small.
**Suggested fix**: Note it in the comment; optionally keep a separate `lapse.lock` key that is read first. Low priority.

### 🟡 A stale success is thrown away and the prompt repeats, `src/components/app-lock.tsx:60-67`
**Problem**: When `returns` changes while a prompt is in flight, the cleanup sets `cancelled = true`; if that first prompt then succeeds, `!cancelled` blocks `setLocked(false)` and the person is asked again. Two concurrent `authenticateAsync` calls are also not supported on every platform.
**Why it matters**: A second Face ID prompt right after a successful one on the first return from background.
**Suggested fix**: Hold an `inFlight` ref and skip starting a new prompt while one is open; do not gate `setLocked(false)` on `cancelled` (unlocking after a real success is always right, only the unmounted case needs guarding).

### 🟡 Switch rows drop their hint, and nothing marks the lock row's state to screen readers, `src/components/settings-row.tsx:44-55`
**Problem**: The switch has `aria-label={label}` which overrides the content, so "Set up on your phone first" (the reason it is disabled) is never read. The Reminders sheet's "Remind me" row has the same shape: its caption ("Before trials end...") is replaced by the label. The Face ID row is also hidden (returns null) until `getBiometrics()` resolves, so the list shifts when it appears.
**Why it matters**: A disabled switch with no reason is a dead end for VoiceOver and TalkBack users; the layout jump affects everyone.
**Suggested fix**: Use `aria-describedby`-style text where supported, otherwise fold the hint into the label (`${label}, ${detail}`) and keep `aria-checked` for the state. Reserve the row height (render it disabled while loading). In `reminder-sheet.tsx` do the same for the caption.

### 🟡 The modal lock view and the sheet are not announced or focused, `src/components/app-lock.tsx:71`, `src/components/reminder-sheet.tsx:44-47`
**Problem**: `aria-modal` on a plain `View` only does something on iOS (`accessibilityViewIsModal`), and nothing moves screen reader focus to the lock when it appears after returning from the background. The lock view has no `role` or label. The sheet's backdrop is correctly hidden and Close is labelled, but the sheet has no accessible name (`Modal` has no label), and the unlock button is the only focusable element, so on web Tab order may still reach the hidden app (the root `aria-hidden` handles screen readers, not keyboard focus).
**Why it matters**: A VoiceOver user returning from the background stays focused on an invisible control.
**Suggested fix**: Set `role="alert"`/`accessibilityLiveRegion="polite"` on the title (or use `AccessibilityInfo.setAccessibilityFocus` on the button on mount); on web use `inert` on the covered root while locked. Label the sheet container with `aria-label="Reminders"`.

### 🟡 The Face ID row's state goes stale, `src/app/(tabs)/profile.tsx:130-136`
**Problem**: `getBiometrics()` runs once on mount; tab screens stay mounted. If the person goes to Settings, enrolls Face ID, and comes back, the row still says "Set up on your phone first" until restart. The reverse (Face ID removed while the lock is on) is not shown at all.
**Why it matters**: The message tells the person to do something they have already done.
**Suggested fix**: Re-run `getBiometrics()` when the app becomes active (an `AppState` listener, or the `useIsFocused` hook from expo-router).

### 🟡 CSV: no BOM, and web download revokes the URL immediately, `src/features/subscriptions/csv.ts:34`, `src/features/subscriptions/export.ts:11-16`
**Problem**: (a) The file has no UTF-8 BOM and the web blob has no charset, so Excel on Windows shows names like "Café" or "Crunchyroll™" as mojibake. (b) `URL.revokeObjectURL(url)` is called synchronously after `link.click()`; Safari and some Firefox versions have not started the download yet, which gives an empty or failed download. The anchor is also not attached to the document, which older Firefox requires.
**Why it matters**: Corrupt names in the export and a flaky web download.
**Suggested fix**: Prefix `'﻿'` (and use `text/csv;charset=utf-8`), append the anchor to `document.body`, and revoke after `setTimeout(..., 0)` or on a delay of a second.

### 🟡 The exported CSV is left in the cache, `src/features/subscriptions/export.ts:20-27`
**Problem**: The file stays in `Paths.cache` after sharing and holds the whole list in plain text, outside the app lock. It is overwritten by the next export, but it persists until the OS clears the cache.
**Why it matters**: The data the lock is protecting is sitting in a readable file. Mild, as the cache is private to the app.
**Suggested fix**: Delete it in a `finally` after `shareAsync` resolves (on Android the share resolves when the sheet opens, so deleting then can break the receiving app; in that case clean up on the next export or on launch instead).

### 🟡 Reminders switch only stores a flag, and does not notice a revoked permission, `src/components/reminder-sheet.tsx:33-41`, `src/app/(tabs)/profile.tsx:154`
**Problem**: Turning reminders off sets `remindersEnabled: false` but nothing cancels scheduled notifications (none are scheduled yet, so this is a note for the step that schedules them). If the person revokes notifications in system Settings while the setting is on, the row still reads "1 day before". The sheet is also unmounted while a permission request is open if the person dismisses it; `setBlocked` then runs on an unmounted component, and `setEnabled` still applies.
**Why it matters**: The setting can say "on" while nothing will arrive.
**Suggested fix**: Re-check `getPermissionsAsync()` when the Profile tab is focused and set the flag false if not granted; cancel scheduled notifications in `setRemindersEnabled(false)` when scheduling lands.

### 🟡 Sheet, rows and cards use literal sizes, `src/components/reminder-sheet.tsx:129-135`, `src/app/(tabs)/profile.tsx:221-290`
**Problem**: Several literals (close button 36, avatar 56, gap 14, padding 20, `borderRadius: 16`, 54 row height, 46x28 toggle) that AGENTS.md prefers as tokens; colors and fonts are tokens. The 36pt close button is under the 44pt target (it has `hitSlop={8}`, which brings it to 52, so it is fine on native but not on web). `PRO_PRICE` is also hard-coded in the file and duplicated into the aria-label and copy.
**Why it matters**: Drift from the design system; price will be wrong when RevenueCat supplies the real one.
**Suggested fix**: Name the sizes at the top of each file or move them into `src/theme`; keep the price in one constant that Pro will replace.

## What I checked and found fine
- **Face ID loop**: iOS goes inactive then active during the prompt; the handler only reacts to `active` after `background`, so no re-prompt. The unlock effect depends on `[locked, canPrompt, returns]` only. Cancel leaves `locked` true and the button re-asks.
- **Persisted state**: both stores keep `version: 1` with no `migrate`, which is correct because zustand merges the saved object over the defaults. Corrupt non-array `cancelled` would crash `summarizeSavings`, which is not worth guarding.
- **Trial caught**: `sub.trial && next === sub.chargeOn` is the same rule as `csv.ts`; a trial whose date has passed counts as paid, as intended.
- **CSV escaping**: quotes doubled, CRLF rows, `=`, `+`, `-`, `@`, tab and CR prefixed; numeric columns come from `toFixed`, not user text.
- **File API**: `new File(Paths.cache, name)`, `create({ overwrite: true })`, `write(string)` match the SDK 57 types; `Sharing.isAvailableAsync` guards the native path. Web branch is not reached on native.
- **Ref guards** (`confirming`, `exporting`, `asking`) are reset in all paths. React Compiler lint is clean.

## Resolution

Fixed:
- Major, app switcher: with the lock on, a plain dark cover goes up as soon as the app goes inactive and comes down on return, so the iOS switcher snapshot shows no data. It doesn't ask for Face ID, so pulling down Control Center or opening the share sheet doesn't re-prompt.
- Major, lockout: `unlock()` now returns `unlocked`, `failed` or `unavailable`. `not_available`, `not_enrolled` and `passcode_not_set` turn the lock off and open the app instead of locking the person out for good.
- Major, web alerts: a `notify()` helper uses the browser's alert on web and `Alert.alert` on phones.
- Major, modals above the lock: a small `useLock` store tells the reminder sheet and the subscription editor to hide while locked. Their state is kept, and they come back on unlock.
- Savings: records keep the original anchor date so month ends don't drift, and add `savedFrom`. A charge due today counts as already paid, except a running trial's, which counts as caught. Each record is counted from its own `savedFrom` (no sentinel date).
- A successful Face ID prompt is never thrown away when the app returns mid-prompt.
- The CSV starts with a UTF-8 BOM so Excel reads names correctly. The web download attaches the link and revokes its URL after a moment.
- Tests for each of the above: 144 passing.

Deferred:
- Android Recents snapshots (FLAG_SECURE through expo-screen-capture), a grace period before re-locking, and the lock failing open when settings can't be read: with the SQLCipher move, which brings the real encryption story.
- Accessibility hints on disabled switch rows, focus moves into the lock view and sheet: in the accessibility pass.
- Re-checking notification permission when the app opens: with the reminder scheduler, which owns permissions.
- The cached CSV file is overwritten on each export, not deleted. It holds only what the person just shared.
- `PRO_PRICE` moves to the RevenueCat offering when Pro is built.
