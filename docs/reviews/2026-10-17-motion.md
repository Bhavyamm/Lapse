# Review, Picks tray and motion pass (commit 4beed6e), 2026-10-17

**Reviewed by**: Sonnet 5.5 (author model: Opus 5.5)
**Scope**: 21 files, `git show HEAD` (`src/app/add.tsx` picks tray, `BottomSheet` used by `ReminderSheet` and `SubscriptionEditor`, `PressScale` replacing pressed-opacity Pressables, animated `Toggle` and `Segmented`, `Appear` and the calendar month slide, `src/utils/motion.ts`, tabs `animation: 'fade'`, compact Done on check-in, `add.test.tsx`)
**Verdict**: Changes requested

## Summary
The motion is built carefully: every `Animated.Value` is driven by one driver only (`BottomSheet`, `PressScale`, `Appear` and `Toggle` are all native; `Segmented` is all JS because it animates `left` and `width`), effects stop their animations on cleanup, `BottomSheet` handles the open-while-closing case for the sheet itself (the effect re-runs, the close callback sees `finished: false`, so the modal is not unmounted), the PressScale conversion kept `role`, `aria-label` and `disabled` on every call site I compared, and the `style` prop is no longer a function only where nothing used one. `tsc` and all 252 tests pass. I read the code and did not run it on a device. The real problems: the sheets stay on screen over the Face ID lock while they animate out, a sheet reopened during its slide-out keeps the previous edits, Reduce Motion removes all press feedback, the picks tray can leave the result list with almost no room while the keyboard is open, and none of the new motion components has a test.

## Critical
None.

## Major
### 🟠 Sheets stay visible over the Face ID lock for the length of the close animation, `src/components/reminder-sheet.tsx:20`, `src/components/subscription-editor.tsx:41`, `src/components/bottom-sheet.tsx:29-49`
**Problem**: Both sheets pass `visible = wanted && !locked` so they step aside when the app locks. Before this commit that unmounted the native `Modal` at once. Now `visible` going false starts a 220 ms slide-out while `mounted` stays true, so the `Modal` (which draws above the lock overlay) keeps showing for that time. The editor shows the price and name of a subscription, on top of the screen that is meant to hide everything. Resuming from background onto the lock can also flash the sheet, then slide it away.
**Why it matters**: The lock exists to hide this data; a 220 ms window every time the app locks with a sheet open defeats it, even if briefly.
**Suggested fix**: Give `BottomSheet` an `instant`/`hidden` input (or a second prop) for "hide now, no animation", and pass `locked` through it so `mounted` flips to false immediately. Add a test in `app-lock.test.tsx`: open the editor, lock, and assert the sheet is gone without advancing timers.

### 🟠 Reopening during the slide-out keeps the old draft and its unsaved edits, `src/components/subscription-editor.tsx:39-44`, `src/components/bottom-sheet.tsx:30`
**Problem**: While the sheet slides out, `mounted` is still true, so `EditorSheet` is still mounted with its own `useState(initial)`. `shown` is only replaced when the new draft is a different object, but `EditorSheet` is keyed by `shown.key`, and the key is stable per subscription or service (`draftFromSubscription` uses `sub.id`, catalog drafts use the service id). So: tap Close on a half-edited price, then within 220 ms tap Edit (detail screen) or the same chip (Add). The sheet slides back up showing the discarded edits, and "Save" saves them, not the draft that was handed in. The comment "Keyed so each opening starts from the draft it was given" is no longer true inside that window. The same window lets Save be tapped twice (the sheet is still interactive while it slides away), calling `onSave` twice.
**Why it matters**: Silent wrong data saved to a price; the window is short but a fast double tap on a chip is exactly how people use the tray.
**Suggested fix**: Key `EditorSheet` by an opening counter incremented whenever `draft` goes from null to non-null (state set during render, like `shown`), not by `draft.key`. Make the sheet non-interactive once closing starts (`pointerEvents="none"` on the holder while `!visible`). Test: close, reopen the same key before the animation ends, and assert the price field shows the draft's price.

### 🟠 The picks tray can leave no room for results while the keyboard is open, `src/app/add.tsx:83`, `:165-176`
**Problem**: `FadeFooter` is absolutely positioned and the screen sits in a `KeyboardAvoidingView`, so with the keyboard up the footer rides above it. The footer is now: 36 top padding + tray (12 + caption ~16 + 10 gap + chip row ~44 + 10 = ~92) + 8 gap + the 64 pt button + bottom inset and 16 = roughly 220 pt with one pick. On an iPhone SE (667 pt, ~260 pt keyboard) that is 667 - 260 - 220 = ~190 pt for the status bar, back row (44), title, search (52) and the list, i.e. the list has almost nothing. The person types a second search, and the results are behind the tray and the fade. (Computed from the styles, not measured.)
**Why it matters**: Picking several services is the point of the change, and searching is how you pick.
**Suggested fix**: Hide the tray (keep the count in the button label) while the keyboard is visible (`Keyboard` events), or collapse it to its title line. Check on a short phone in Expo Go.

## Minor
### 🟡 Reduce Motion removes all press feedback, `src/components/press-scale.tsx:19-21`
**Problem**: `to()` returns early under Reduce Motion, and the old pressed opacity was deleted from every call site (`pill-button`, home, profile, pro, subscription rows, trial, check-in). With the setting on, a press shows nothing until the action happens. Reduce Motion should remove movement, not feedback.
**Suggested fix**: Under Reduce Motion, apply an opacity dip (via `onPressIn`/`onPressOut` state or the Pressable style callback) instead of the scale.

### 🟡 Reduce-motion state has two sources and a startup gap, `src/utils/motion.ts:4-13`, `src/hooks/use-reduce-motion.ts`
**Problem**: `motion.ts` keeps a module flag that is `false` until `isReduceMotionEnabled()` resolves, so anything that mounts in the first moments (the first screen's `Appear`, the first `Toggle`) animates even with the setting on. `check-in.tsx` still uses the hook, so there are now two sources of truth. The module listener is never removed (fine for a singleton) and `addEventListener?.` hides a missing API instead of failing.
**Suggested fix**: Keep one source: make `useReduceMotion` read the same store (or have components use the hook), and accept the first-frame gap only for the one-shot reads.

### 🟡 `BottomSheet` keyboard handling is unverified on Android, `src/components/bottom-sheet.tsx:58-62`
**Problem**: `behavior="height"` inside a transparent, `statusBarTranslucent` `Modal` on an edge-to-edge Android window (SDK 57 default) is known to resize twice or not at all. The editor has `maxHeight: height * 0.92`, which is larger than the room left above a keyboard, so on both platforms the header and Close can be pushed off the top when a text field is focused on a short phone. `pointerEvents="box-none"` as a prop is also the legacy form; the style form is the supported one.
**Suggested fix**: Use `padding` on both platforms (or the `Keyboard` height as a bottom offset), subtract the keyboard height from the sheet's `maxHeight`, and check the price field on a small Android in Expo Go.

### 🟡 `animateLayout` can leak onto an unrelated change, `src/utils/motion.ts:35-42`, `src/app/add.tsx:50-65`, `src/components/segmented.tsx:60`
**Problem**: `configureNext` applies to the next layout commit, whatever it is. `saveDraft` calls it and then closes the editor; for Segmented, a sort change that happens not to move any row produces no layout, so the pending animation fires on the next layout (a keyboard resize, the tray's `onLayout` height update). The tray's own `setFooterHeight` pass is a second layout that is not animated, so the list's bottom padding jumps while the rows glide. On Android's new architecture `LayoutAnimation` works without the experimental flag, but `create`/`delete` opacity on views inside a `Modal` root or a `FadeFooter` is not something I could confirm without a device.
**Suggested fix**: Animate only the footer/list change you mean (use `Appear` for the tray, a wrapper for the list), or accept it and test on Android; at least skip `animateLayout` in `saveDraft` when the editor is closing a non-custom draft.

### 🟡 Picked rows and the tray are announced as plain buttons, `src/app/add.tsx:134-140`, `:165-168`
**Problem**: A picked row is a `role="button"` whose label flips between "Add X" and "Remove X, picked", with no state. Using `role="checkbox"` with `aria-checked` (label "X, price") reads better and survives translation. The tray's "2 picked · $19.98 a month" and its chips appear with no announcement, so a screen reader user gets no confirmation after a pick.
**Suggested fix**: Use `role="checkbox"`/`aria-checked`; give the title `aria-live="polite"`.

### 🟡 The tray total counts trials at full price, `src/app/add.tsx:197`
**Problem**: "$X a month" sums every pick's price, including drafts with `trial: true`, which will not be charged until the trial ends, and treats an unparseable price as 0 without saying so. Home and Profile exclude running trials from totals (the Pro review relied on that), so the figures will not match after saving.
**Suggested fix**: Skip trial drafts in the sum (or label them), as `buildOverview` does.

### 🟡 `Appear` replays the whole month and sits outside the tab's gap, `src/app/(tabs)/calendar.tsx:63-66`, `src/components/appear.tsx:16-27`
**Problem**: `key={offset}` remounts the grid and list on each month change (fine), but tapping the arrows fast restarts the spring from zero each time, so the content blinks to opacity 0 on every tap; nothing shows during a fast run through months. At the clamp (next at the last month) `offset` does not change, so there is no replay, but `direction` still changes. The `month` style re-adds a `gap: spacing.md` equal to `TabScreen`'s, which matches today but will drift if one changes.
**Suggested fix**: Start from a partial opacity (0.4) so rapid taps do not blank the content, and share the gap token.

### 🟡 Test gaps, `src/components/`, `src/utils/`, `src/__tests__/`
**Problem**: Nothing covers the new components: `BottomSheet` (opens, closes after the animation, `onClose` from scrim/Close/back, reopen while closing, hidden while locked, no children left mounted when closed), `PressScale` (passes `disabled`, `role`, `aria-*` and `onPressIn/Out`; a disabled `PillButton` does not scale or press), `Toggle`/`Segmented` (end positions, `aria-checked`), `motion.ts` (Reduce Motion skips `LayoutAnimation` and the slide), and the Done pill (it has `role="button"` and the accessible name "Done"). `add.test.tsx` covers pick/unpick and the total but not removing from the tray with the chip's X, editing a pick in place keeping its position, or the broken-draft-opens-editor path in `save`. `app-lock.test.tsx` does not exercise sheets.
**Suggested fix**: Add `bottom-sheet.test.tsx` and `press-scale.test.tsx` beside the components with fake timers, and extend `add.test.tsx` and `app-lock.test.tsx` with the cases above.

## Nits
- `src/components/toggle.tsx:12`: `return progress.setValue(...)` returns `void` from the effect; write it as two statements so a future change to `setValue` cannot be read as a cleanup function.
- `src/components/bottom-sheet.tsx:56`: the scrim `Pressable` has `aria-hidden` and `accessible={false}`; keep one (`accessible={false}` is enough and avoids the AGENTS.md prop question).
- `src/components/press-scale.tsx:14`: if a caller's style ever contains a `transform` it is silently overridden by the scale; none do today (checked `app/` and `components/`), but note it in the doc comment.
- `src/app/check-in.tsx:378`: the Done pill drops `aria-label`; the text child gives the name, so this is fine, just confirm in the screen reader.
- `src/app/(tabs)/_layout.tsx`: tabs `animation: 'fade'` is not gated by Reduce Motion; a cross-fade is usually acceptable, but check the option exists on the pinned navigation version.

## Resolution

Fixed:
- Major, sheets over the Face ID lock: `BottomSheet` takes `hideNow`, and both sheets pass the lock state, so they vanish at once (no slide) when the lock comes up and return when it goes. Test added.
- Major, reopening mid-slide: the editor is keyed by an opening counter, so every opening starts from the draft it was given, and the sheet is inert while sliding away. Test added.
- Major, tray with the keyboard: the picks tray hides while the keyboard is open and comes back when it closes.
- With Reduce Motion, buttons dim while held instead of scaling, so presses still show.
- Picked rows carry `aria-selected`, and picking or removing is announced with the running count.
- The tray's monthly total leaves out free trials.
- Calendar months fade in from part-way, so fast taps never blank the month.
- Tests: BottomSheet (open, slide away, hide at once), the tray's remove chip, reopening the editor fresh. 257 tests.

Kept as is:
- One reduce-motion source per use: components that render animations read the hook, and imperative helpers read the module flag; the flag starts false for a moment at launch, which only means the very first press may animate.
- `KeyboardAvoidingView` in a transparent modal on edge-to-edge Android and `LayoutAnimation` on the new architecture: to check on an Android device with the development build.
- Toggle, Segmented and PressScale are covered through the screens that use them.
